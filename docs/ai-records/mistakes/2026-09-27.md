### 巡线参数 UI 只暴露部分配置字段（前后端配置字段同步）

- **现象**：网页巡线调参区只有黑色 V 上限和左右裁剪，缺少 HSV 其他上下限、上方裁剪及原配置中的多项控制参数。
- **原因**：后端配置已经使用 `lower/upper` 三元组和多项控制字段，但前端 `collectLineConfig()` 曾把 HSV 和大部分控制参数硬编码，且视觉处理中的上方裁剪写死为 `5/8`。
- **修复**：新增可配置 `crop_top`；前端完整映射后端配置，提供 29 个滑块/方向项；增加上方裁剪测试和 HSV 范围校验。
- **预防**：新增巡线配置字段时，同时检查默认配置、校验、图像处理、网页加载/收集和测试，避免只改后端或只改控件。

### 巡线滑块只点击保存且与预览分离（实时保存与布局）

- **现象**：参数卡片距离巡线画面较远，调参必须额外点击保存按钮。
- **原因**：参数卡片位于通用控制网格的后续单元，滑块事件只更新页面显示，没有触发配置接口。
- **修复**：将巡线参数卡片置顶并横跨控制区；滑块/方向变化使用防抖自动保存，同时保留手动保存按钮。
- **预防**：调参类界面需要同时验证预览邻近性、交互后的持久化和网络断开时的可见状态。

### 巡线 PID 缩放遗漏导致持续右转（PID scale）

- **现象**：线中心只偏离裁剪中心约 0.5 像素时，巡线仍持续输出同一方向的转向。
- **原因**：原程序在 `PID_init()` 中把 P/I/D 除以 `scale=1000`，网页移植的 `SimplePID` 直接使用了 UI 数值，导致 `P=271` 对 0.5 像素误差产生约 `-135.5`，超过 `|PID|<8` 直行死区。
- **修复**：网页巡线 PID 已恢复原程序的 1000 倍缩放语义，并增加初始化/实时更新两条路径的回归测试；若物理转向仍反向，再调整 `direction`。
- **预防**：移植控制算法时不仅核对参数名和默认值，还要逐项核对初始化缩放、死区、限幅和执行器方向。

### PowerShell 向 SSH 内嵌 Python 正则时发生本地语法解析（PowerShell/SSH 引号）

- **现象**：在 PowerShell 中通过 `ssh.exe "python3 ..."` 传递带 `(?:...)` 的 Python 正则时，PowerShell 在本地将其拆解为命令片段，远端脚本未执行。
- **原因**：多层命令行同时经过 PowerShell、SSH 和远端 Shell 的引号/括号解析，内嵌正则没有安全跨过边界。
- **修复**：将完整 Python 脚本在本地编码为 Base64，远端解码后直接交给 `python3`，避免传输内容再被 Shell 解析。
- **预防**：PowerShell 通过 SSH 执行多行 Python/JSON/正则时，优先使用 Base64 或已验证的脚本文件，不把复杂源码直接塞进双引号命令字符串。
