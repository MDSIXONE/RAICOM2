# 项目结构索引（project-index）

本 skill 是项目的结构地图：**索引存于本技能自带资源**（`.agents/skills/project-index/INDEX.md`，大项目按模块拆分到 `details/` 子目录）。写入与读取都经由本技能，保证索引始终是权威、最新的结构视图。

## 存储布局

```
.agents/skills/project-index/
├── SKILL.md              # 本文件（规则与触发入口）
├── INDEX.md              # 主索引：总体结构 + 功能索引表（小到可一次全读）
└── details/              # 可选：大项目按模块拆分的功能详情文件
    └── <模块名>.md
```

## 首次使用（初始化索引）

若 `INDEX.md` 不存在：扫描项目结构，**跳过噪音目录**（`.git`、`node_modules`、`dist`/`build` 等构建产物、`.agents` 内部细节），按文末「索引模板」生成 `INDEX.md`，并告知用户索引已生成。

## 更新索引（写入）

**触发时机**：
- AI 完成对项目结构的总结后（项目初始化完毕、用户要求总结项目结构、梳理功能模块之后）；
- 项目结构大改后：新增/移动/重命名主要模块、新增服务或入口、目录重组；
- 用户明确要求"更新项目索引 / 记录项目结构"。

**流程**：
1. 重新扫描项目结构，提取：裁剪噪音目录后的总体目录树、功能/模块清单。
2. 为每个功能/模块记录：位置（相对路径）+ 一句话职责说明。
3. 更新 `INDEX.md`：
   - `## 总体结构`：裁剪后的目录树，标注各主要目录的职责；
   - `## 功能索引`：表格 `功能/模块 | 位置 | 一句话说明 | 详情`；
   - 需要更细说明（关键文件、入口、数据流）的模块，写入 `details/<模块名>.md` 并在表格中链接。
4. 保持 `INDEX.md` 小到可一次全读：接近单次阅读上限时，把详情拆入 `details/`，主索引只保留总体结构与索引表。
5. 更新「更新时间」，告知用户索引已更新。

**不做**：单次代码小改动、修 bug、微调不触发更新；索引只记位置与职责，不复制代码内容。

## 读取索引（快速了解项目）

**触发时机**：
- 新会话开始需要了解项目 → 先读 `INDEX.md`；
- 用户询问"项目结构 / 有哪些模块 / XX功能在哪"；
- 开始新任务前，用索引定位相关模块位置，再深入具体文件。

**流程**：
1. 读 `INDEX.md` 全文（小而完整，一次读完）。
2. 按任务需要沿功能索引定位位置，再读取相关目录/文件。
3. 需要更细说明时，读对应 `details/<模块名>.md`。
4. `INDEX.md` 不存在或明显过期（与磁盘结构不符）→ 先走「更新索引」流程再回答。
